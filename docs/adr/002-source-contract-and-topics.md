# ADR-002 원천 계약과 토픽

- 상태: 확정
- 날짜: 2026-10-27

## 맥락

원천(시뮬레이터)은 착륙 구역에 쓰기만 하고, 착륙 구역부터는 플랫폼의 것이다(원천 ADR-007). Kafka 모드의 착륙 구역은 토픽이다.
원천이 정한 것은 토픽 이름(`<source>.events`, `<source>.manifest`), 키(`entity_key`), 값(봉투 JSON 그대로), 메시지 시각(`emitted_at`)이다. 브로커, 토픽 만들기, 파티션 수, 보존 기간은 플랫폼이 정한다.
원천 레포의 스키마(`schemas/`)는 원천이 고치면 바뀐다. 플랫폼이 그 파일을 그때그때 따라가면, 원천이 무엇을 바꿨는지 모르는 채 파이프라인의 동작이 바뀐다.

## 결정

1. **토픽은 출처 시스템마다 둘**: `erp|mes|eam` × `.events`·`.manifest`, 모두 여섯이다. 출처 목록은 봉투의 `source`와 같고, 테스트(`tests/test_contracts.py`)가 `infra/create_topics.sh`와 봉투를 맞춰 본다.
2. **토픽은 스크립트만 만든다**: 자동 생성(`auto_create_topics_enabled`)을 끈다. 이름을 잘못 쓴 토픽이 조용히 생기지 않고, 파티션 수가 브로커 기본값으로 정해지지 않는다. 토픽이 없으면 방출기는 버리지 않고 기다린다(원천 ADR-007). 스크립트는 여러 번 돌려도 같은 결과다.
3. **키는 `entity_key`**: 같은 개체(호선·블록·설비)는 같은 파티션에 들어가, 파티션 안에서는 도착 순서가 지켜진다. 개체별 `seq`의 빈 번호를 찾는 대사(4단계)가 이 순서에 기대지는 않는다. 지연 때문에 도착 순서와 `seq` 순서가 원래 다르다(원천 ADR-005).
4. **파티션 수**
   - `.events`는 3개: 2단계에서 같은 소비자 그룹에 소비자 둘을 붙여 리밸런스를 연습하려면 파티션이 소비자보다 많아야 한다. 이 크기에서 처리량 때문에 더 늘릴 까닭은 없다.
   - `.manifest`는 1개: 마감 집계는 시스템마다 하루 한 건이고, 같은 시스템의 집계는 키(`MANIFEST-MES` 등)가 하나라 어차피 한 파티션에 든다.
   - 파티션 수는 지금 고정한다. 늘리면 키와 파티션의 짝이 바뀌어, 같은 개체가 늘리기 전후로 다른 파티션에 있게 된다.
5. **보존 기간은 무기한**(`retention.ms=-1`)
   - 5년치가 수만 건이라 작다.
   - 메시지 시각이 가상 시각(`emitted_at`, 2026년 11월부터 5년)이라 시간 기준 보존은 실제 시각과 어긋난다. 지울지 말지가 시뮬레이션 날짜에 따라 정해진다.
   - 토픽이 처음부터 다 남아 있어야 2단계의 오프셋 되감기, 7단계의 스트림 상태 다시 만들기를 할 수 있다.
6. **복제 1**: 브로커가 하나다(ADR-001).
7. **원천 계약은 태그로 고정한 사본을 쓴다**
   - 원천 `v0.3.0`의 `schemas/`(봉투, payload 10종, 예시, 재발행 요청)를 `contracts/`에 그대로 복사한다. `contracts/VERSION`에 태그와 커밋, 다시 복사하는 명령을 적는다.
   - 사본은 손으로 고치지 않는다. 원천이 새 태그를 내면 다시 복사하고, `tests/test_contracts.py`가 깨지는 곳을 보고 고친다. 바뀐 내용은 diff로 리뷰한다.
   - 배치와 스트림은 이 사본만 본다. 3단계의 스키마 검증, 4단계의 재발행 요청(`replay_request.json`)이 모두 이 사본을 쓴다.
   - 봉투는 원천 0단계에서 고정됐고, 이후에는 `event_type`과 payload 필드를 더하기만 한다(원천 봉투 계약). 플랫폼은 모르는 `event_type`을 버리지 않고 격리 표로 보낸다(3단계).

## 결과

- 토픽 모양이 스크립트 하나와 이 문서에 모여 있다. Console에서 보이는 토픽과 다르면 스크립트를 다시 돌린다.
- 원천이 계약을 바꿔도 플랫폼은 사본을 다시 복사하기 전까지 영향을 받지 않는다. 대신 다시 복사하는 일을 잊으면 새 이벤트 종류가 격리 표에 쌓인다. 5단계 감시에서 격리 표 행 수를 본다.
- 무기한 보존이라 토픽은 줄지 않는다. 처음부터 다시 하려면 Redpanda 볼륨을 지우고(`docker compose down -v`) 스크립트로 다시 만든다.
- 파티션 수를 바꾸는 것은 이 ADR을 바꾸는 일이다. 바꿀 때는 토픽을 새로 만들고 처음부터 다시 받는다.
